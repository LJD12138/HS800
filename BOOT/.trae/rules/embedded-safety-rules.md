# 嵌入式软件安全与代码变更准则

## 1. 代码变更与维护准则
1. **最小修改原则**：修改现有代码时，严格尊重已有模块的架构风格与变量命名习惯，非必要不重构或大面积重命名变量，避免扩大 diff 范围。
2. **完整性保持**：严禁随意删减与修改任务无关的已有注释、宏开关、调试日志和函数定义。
3. **接口兼容性**：修改具有外部链接的全局函数或结构体时，必须保证所有既有调用方兼容。

## 2. 内存与指针安全
1. **严禁动态内存分配**：除系统初始化特定专用堆外，运行时严禁使用 `malloc()` / `free()`，避免内存碎片及泄漏。
2. **入参非空防御**：所有对外函数接收指针入参时，必须首先进行非空指针判断（如 `if (p_buf == NULL) { return ...; }` 或断言）。
3. **安全边界函数**：所有字符串复制、缓冲区操作必须使用带边界检查的 API（如 `snprintf`、`strncpy`），严禁使用无边界保护的 `sprintf`、`strcpy`。

## 3. 并发与中断安全
1. **中断服务函数 (ISR) 限制**：
   - ISR 中严禁执行耗时循环、阻塞等待或调用可能引起任务调度的系统 API。
   - ISR 遵循“快进快出”原则，仅负责清标志位、暂存数据、通过队列或信号量唤醒任务。
2. **共享变量保护**：中断与任务间共享的变量必须使用 `volatile` 修饰，在多任务并发访问时必须使用临界区或互斥量保护。

## 4. 防御性编程
1. **变量显式初始化**：局部变量定义时建议显式赋初值，防止野指针或未初始化状态引发隐蔽故障。
2. **switch 完整性**：所有 `switch-case` 语句必须包含 `default` 分支进行容错或断言捕获。
3. **宏安全包裹**：宏参数及整个宏表达式必须使用括号包裹，防止运算优先级产生歧义。
