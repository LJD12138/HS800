# Git 提交信息生成规则

当生成 Git 提交信息时，遵循以下规则：

## 语言要求
- 提交信息必须使用**中文**编写。

## 标题格式
- 标题必须以 `发布vX.Y.Z版本，` 开头，后接一句话概述本次提交的主要内容。
- 版本号 `vX.Y.Z` 的获取方式：
  - 优先从当前项目的 `board_config.h` 中的 `boardSOFTWARE_VERSION` 宏定义获取。
    - 宏值格式示例：`"G3604_Ver_4_0_0(230V)"`
    - 提取 `Ver_` 之后的数字部分 `4_0_0`，将下划线转换为点号，并加 `v` 前缀，得到 `v4.0.0`。
    - 括号中的后缀（如 `(230V)`）不写入标题。
  - 若项目中不存在 `board_config.h`，则从其他可能包含版本号的文件中查找（如 `version.h`、`config.h` 等），按同样的下划线转点号规则处理。
- 概述需简明扼要，能体现本次提交的核心目的（如"更新多项功能与修复"、"修复XX问题"等）。

## 正文格式
- 正文以编号列表（`1.`、`2.`、`3.`...）逐条描述具体修改点。
- 每条以动词开头，如"新增"、"优化"、"修复"、"调整"、"删除"、"重构"等。
- 每条描述需清晰说明改了什么，避免空泛表述。
- 仅列出本次提交实际涉及的修改，不要编造未发生的改动。

## 示例

发布v6.0.4版本，更新多项功能与修复
  1.新增逆变输出频率自动记忆功能
  2.优化升级流程逻辑与错误处理机制
  3.调整打印队列与DCAC升级相关判断条件

## 其他
- 不要在提交信息中包含英文 Co-authored-by 等署名行，除非用户明确要求。
- 不要输出 Markdown 代码块标记，直接输出纯文本提交信息。
