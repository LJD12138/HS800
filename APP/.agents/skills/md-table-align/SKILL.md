# Markdown 表格排版（列宽对齐）

只重排表格行的空白，表格文字一个字不改。默认 **空格填充 + 末列补齐**，竖线在编辑器里严格对齐。

## 为什么默认不用 Tab

本项目编辑器字体是**比例字体**（`editor.fontFamily: 黑体`），Tab 的视觉宽度由编辑器/预览各自计算，同一份文件在不同工具里会错位（实测正文行竖线比表头偏 2 列）。空格填充与字体无关，因此默认 `--mode spaces`；确需 Tab 风格时才用 `--mode tabs`，且必须让编辑器 tab size 与 `--tab-size` 一致。

## 何时用

- 用户说“优化排版”“表格没有对齐”“格式化这些表格”。
- 典型对象：`APP\Docs\百酷通讯协议文档\*.md`（中英文混排、手工补空格的文件）。

## 硬规则（违反即中止）

- **只改表格行**：非表格行、缩进、空行、行尾、代码块一律不动。
- **不改文字**：字段名、数值、单位、链接、标点全部原样；脚本写回前逐格比对，内容不一致就整表跳过。
- **不改标题文本**：分册用 `[00 §7.2](00_协议总纲.md#72-...)` 这类锚点引用总纲章节，改标题会让链接失效。
- **不搬内容**：不把长枚举从单元格挪到列表、不合并/拆分表格，结构调整要先问用户。
- 换行符（LF/CRLF）与 UTF-8 BOM 原样保留。

## 宽度口径（决定能不能对齐）

用 `C:\Windows\Fonts\simhei.ttf`（黑体）实测字宽，ASCII/反引号 = 0.5 em（1 列），CJK = 1 em（2 列），`§ ℃ × → — “ ” ≥ ≤ ↔ ·` 等歧义宽度字符在该字体下**同样是 1 em（2 列）**，因此默认 `--ambiguous-width 2`。换成西文字体或 VS Code 默认字体时，歧义字符为 1 列，需要显式 `--ambiguous-width 1`。

- 东亚宽字符（`W`/`F`）恒按 2 列。
- 分隔行用“破折号 + 空格”填满列宽，竖线不贴破折号。

## 末列策略

- 默认 `--pad-last`：末列也补齐，整表右侧竖线成一列（用户说的“对齐”就是这个）。
- `--no-pad-last`：末列不补，行更短，但右侧竖线参差；表格过长（末列 >150 列）时可用。
- 不指定时脚本沿用表格现状：任一表格行末列前有多余空白，或分隔行末格多于 3 个破折号 → 视为矩形。

## 用法

`<SKILL_DIR>` = 本 SKILL.md 所在目录。

```powershell
# 只检查（退出码 1 = 有表格需要重排或跳过）
python "<SKILL_DIR>\scripts\md_table_align.py" check "<文件或目录>"

# 重排并写回（默认 spaces + 末列补齐 + 歧义字符按 2 列）
python "<SKILL_DIR>\scripts\md_table_align.py" apply "<文件或目录>"

# 末列不补（行更短）
python "<SKILL_DIR>\scripts\md_table_align.py" apply "<文件或目录>" --no-pad-last

# Tab 风格（仅在编辑器 tab size 与参数一致时使用）
python "<SKILL_DIR>\scripts\md_table_align.py" apply "<文件或目录>" --mode tabs --tab-size 4
```

- 路径可以是单个文件，也可以是目录（目录只处理顶层 `*.md`，按文件名排序）。
- 表格允许 0~3 列缩进和 `> ` 引用前缀，脚本会原样保留；缩进达到 4 列的行按缩进代码块跳过，围栏代码块整段跳过。
- 输出含义：`改写 N 张` 为实际写盘的表数量；`跳过` 表示该表列数不一致或内容校验失败，已保持原样，需人工看。

## 完成后校验

1. 再跑一次 `check`，应为“待重排 0 张”（幂等）。
2. 与改前快照比对：去掉空白、把分隔行只保留对齐标记后，逐行应完全一致。
3. 行数不变、无残留 Tab；`apply` 再跑一次应为 `改写 0 张`。
4. 若怀疑字体不同，用 `font_w` 方式复核：按目标字体真实 advance 逐字符累加，要求每列竖线落在同一列。

## 常见坑

- **Tab 不可靠**：比例字体下 Tab 宽度由渲染器决定，模板里已有 Tab 的表在套用本脚本时会自动转为空格。
- **歧义宽度字符**：黑体下 `§ ℃ × →` 都是全角；漏算会让整表偏 1~2 列。
- **列数不一致的表**：按未转义 `|` 切分后各行列数不同会被跳过；`\|` 视为单元格内的字面竖线，`\\|` 中的 `|` 仍是分隔符。
- **只识别以 `|` 开头的表**：省略前导竖线的 GFM 表格不处理，避免误判普通段落。
- **非 UTF-8 文件**：直接跳过并提示，不猜测编码。
- **不要顺手美化**：合并空行、去行尾空格、改块引用换行都超出“排版”范围，除非用户明确要求。
